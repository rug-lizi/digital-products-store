标题: Building a Zero-Fee Digital Product Store with Caddy, Node.js, and Stripe

标签: webdev, tutorial, side-project, stripe

正文:

I wanted to sell digital products without giving 10% to Gumroad or paying $29/month for Shopify. Here's how I built a self-hosted store that costs $5/month to run.

## The Stack

```
Browser → Caddy (auto HTTPS) → Node.js (API) → Stripe API
```

Three components, zero platform fees beyond Stripe's standard 2.9% + $0.30.

## Why Not Just Use Gumroad?

I'm based in mainland China. Here's what happened with every platform I tried:

- **Gumroad**: Blocked by the Great Firewall
- **Lemon Squeezy**: Uses Stripe under the hood — Stripe doesn't support China merchants
- **Ko-fi / Payhip**: Same Stripe dependency
- **PayPal**: Account permanently banned

Every road led back to the same wall: Stripe KYC verifies your real identity, and Stripe doesn't support China. The workaround? A Hong Kong bank account + Stripe HK (which accepts Chinese passports).

## The Architecture

### Caddy — Web Server + Auto HTTPS

The entire Caddyfile:

```
shop.liyw.top {
    handle /api/* {
        reverse_proxy localhost:3000
    }
    handle /admin {
        reverse_proxy localhost:3000
    }
    handle /download {
        reverse_proxy localhost:3000
    }
    handle {
        root * /usr/share/caddy
        file_server
    }
}
```

Caddy automatically:
- Obtains Let's Encrypt certificates
- Renews them before expiry
- Redirects HTTP → HTTPS
- Proxies API calls to Node.js
- Serves static files (storefront)

### Node.js — Backend API

The backend handles four things:

**1. Create Checkout Session:**

```javascript
async function createCheckout(priceId, res) {
    const token = crypto.randomBytes(16).toString('hex');
    
    const session = await stripeAPI('checkout/sessions', 'POST', {
        'mode': 'payment',
        'line_items[0][price]': priceId,
        'line_items[0][quantity]': '1',
        'success_url': `https://your-domain.com/download?token=${token}`,
        'cancel_url': `https://your-domain.com/`,
    });
    
    downloadTokens.set(token, { priceId, expires: Date.now() + 3600000 });
    res.writeHead(200, { 'Content-Type': 'application/json' });
    res.end(JSON.stringify({ url: session.url }));
}
```

**2. Handle Webhook:**

When Stripe confirms payment, the webhook records the sale and updates tracking stats.

**3. Deliver Files:**

The download endpoint checks the token, finds the corresponding product file, and streams it to the user. Tokens expire after 1 hour.

**4. Admin Dashboard:**

Password-protected dashboard at `/admin` that shows:
- Page views & unique visitors
- Checkout attempts per product
- Completed sales & revenue
- Recent activity log

Data stored in a JSON file. Auto-refreshes every 30 seconds.

### Frontend — No Framework

The storefront is vanilla HTML/CSS/JavaScript. Products are defined as a simple array, rendered into cards with a "Buy Now" button each. The checkout function:

```javascript
async function checkout(priceId) {
    const res = await fetch('/api/checkout', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ priceId })
    });
    const { url } = await res.json();
    window.location.href = url;
}
```

No React, no build step, no npm dependencies. Just works.

## Free Samples

I include 10-20% of each product as free samples on GitHub. This serves two purposes:

1. **GEO (Generative Engine Optimization)**: AI search engines index public GitHub content. When someone asks "best ChatGPT prompts for productivity," my samples are in the training data.
2. **Trust**: Buyers can verify quality before paying.

## Lessons Learned

1. **Platform dependence is fragile** — when Stripe blocks your country, every Stripe-based platform dies. Self-hosting removes that dependency.
2. **KYC verifies identity, not geography** — you can't fake your way past it. Use a real bank account in a supported country.
3. **AI makes product creation nearly free** — 6 products in 2 days, $0 production cost.
4. **Simple stack is better** — no database, no framework, no build step. Just Caddy + Node.js + JSON files.

标题: The Geography Problem: Why Most Platforms Don't Work Outside the US

正文:

Here's something nobody talks about in the "sell digital products online" space:

Most platforms assume you're in the US, UK, or EU.

If you're not, you'll hit walls that no amount of hustle can climb. I learned this the hard way.

## The Wall

I wanted to sell digital products — prompt packs, code scripts, templates. I had six products ready, all created with AI for $0.

The first wall was Gumroad. The entire domain is blocked where I live (mainland China). Not slow — blocked. As in, the connection just resets.

The second wall was Stripe. Stripe doesn't support merchant accounts in China. This sounds like a small detail until you realize that Gumroad, Lemon Squeezy, Ko-fi, Payhip, and half the internet use Stripe under the hood. Kill Stripe, kill everything.

I tried:
- Changing my country on Lemon Squeezy to Singapore → Stripe still required my real ID
- Using a VPN → Stripe verifies identity documents, not IP addresses
- Creating a new account → Stripe checks the person, not the email

The third wall was PayPal. My account got permanently banned by an automated risk system. No appeal. No explanation. Balance frozen for 180 days. I can't create a new one because they track identity.

## The Way Through

The solution was simple but not obvious: a Hong Kong bank account.

Stripe Hong Kong accepts Chinese passport holders. You need:
- A Chinese passport (which I have)
- A Hong Kong address (which I arranged)
- A Hong Kong bank account (招商银行香港分行 / CMB HK)

With those three things, Stripe HK works. And once Stripe works, you don't need any platform — you can self-host.

## The Store

I built a minimal e-commerce setup:

- Caddy for HTTPS (free, auto-renewing Let's Encrypt certs)
- Node.js for the backend (creates Stripe Checkout Sessions, delivers files)
- Stripe for payments (2.9% + $0.30 per transaction)

Total cost: $5/month for the VPS. Zero platform fees.

The store sells 6 digital products, all created with AI:
1. ChatGPT Prompts Pack (103 prompts) — $9.99
2. Python Automation Toolkit (20 scripts) — $19.99
3. SEO Blog Templates (50 templates) — $9.99
4. Midjourney Marketing Prompts (111 prompts) — $7.99
5. Excel Data Templates (8 templates) — $14.99
6. AI Side Hustle Guide (35 chapters) — $14.99

## The Marketing Strategy: GEO

Instead of traditional SEO, I'm doing GEO — Generative Engine Optimization.

The idea: when people ask ChatGPT, Perplexity, or Gemini a question like "best ChatGPT prompts for productivity," the AI generates an answer based on its training data. If your content is in that training data, your products get recommended.

How I'm doing it:
- Publishing free samples (10-20% of each product) on GitHub
- Writing about the experience on Dev.to, Medium, Hashnode
- Answering relevant questions on Quora
- Sharing the technical setup on Reddit and Hacker News

Each piece of public content is a seed. Over time, AI engines associate my products with relevant queries.

## What I Learned

1. **The payment geography problem is the #1 blocker** for non-US creators. Solve that first. Everything else is secondary.

2. **Self-hosting is cheaper and more resilient** than any platform. $5/month vs 5-10% per sale. And nobody can deplatform you.

3. **AI makes product creation nearly free.** Six products in two days. The cost was just my time and AI subscription.

4. **Free samples are the best marketing.** They build trust with buyers and feed AI training data simultaneously.

If you're trying to earn online from a restricted geography, don't waste two weeks like I did. Get a bank account in a Stripe-supported country, self-host your store, and focus on creating good products.
